# 本机账号与招募服务器 / v0.9

完整解压 Windows 包后双击 `WildsAndWonders.exe`，自动启动或连接附带的本机服务，玩家无需另装 Node.js。仅监听 `127.0.0.1:18765`，浏览器可访问 `http://127.0.0.1:18765`。关闭窗口后服务继续运行，下次复用；关闭电脑后停止，下次开游戏时再次启动。当前为本机单人 Demo，没有公网访问、账号找回或多人同步战斗。

## 源码启动

需要 Node.js 24+，在项目根目录执行：

```powershell
node server/server.cjs --game-dir .
```

或运行 `server/启动服务器.ps1`。发行包含运行时及许可。桌面入口 `desktop/Program.cs` 会核对服务版本和游戏目录，避免连接到另一份程序。

## 账号、进度与迁移

用户名 4–32 位英文字母、数字或下划线，不区分大小写；密码 10–128 位。主角名字 2–16 个文字，允许中英日、数字、空格、下划线、短横线和中点；名称可重复，账号唯一。注册后选择男女形象并命名，扩展可修改。登录会话有效 30 天，退出立即失效。

进度、展示角色、主角、语言、布阵和偏好按账号保存。变化约 350 毫秒后提交，扩展显示状态；保存带版本号，拒绝多窗口覆盖较新数据。断线时保留本窗口待同步内容和账号本地缓存，重试后再同步；缓存不自动覆盖服务器。退出账号先完成保存，失败不会退出；关闭桌面窗口也会等待保存。

战斗在客户端模拟，不保存进行中的战斗，下次回到准备阶段或已保存胜利界面。20 关按连续通关进度保存，每五关组成一章。当前服务接受客户端通关记录，未实现公网游戏所需的战斗服务端验证。

旧版 WebView2 存档保留。首次连接复制迁移备份，注册勾选「导入旧版本本地进度」才导入新账号；原存档不删除。浏览器只能读取自身可访问的旧数据，不能直接读桌面 WebView2 存档。

## 招募、奖励与装备

新账号初始化为橡木卫士、逐风游侠两位伙伴及 60 张券。主角是剧情身份，不计入持有伙伴或战斗位置。升级时，数据库已有保存进度的旧账号保留之前开放的八位伙伴。

招募由服务器生成并保存，客户端不能直接写入角色持有物、余额或保底。四池和武器属性在项目根目录 `gacha-data.js` 定义，打包后从 `game/gacha-data.js` 读取。规则如下：

- 六星基础 2%、五星 8%、四星 90%。每池独立保底：60 抽内六星，10 抽内五星或以上。六星重置两种计数，五星重置十抽计数，六星优先。
- 限定角色六星为月影猎手，常驻角色为曙光骑士；限定武器六星为弦月遗音，常驻武器为黎明誓约。限定六星 100% 为展示对象，没有 50/50；常驻不含限定六星。
- 重复四 / 五 / 六星转为 10 / 50 / 200 星尘，100 星尘换 1 券。本期测试池无截止日期，没有付费接口。
- 每关首次保存通关记录奖励 10 券，20 关最多 200 券；重复保存或重打不重复发放。
- 每位已拥有伙伴可装备一把已获得武器，同一武器不能同时供两人使用；转交自动卸下原使用者装备。重复武器转星尘，不增加装备数量。

抽卡携带请求 ID，扣券、结果、持有物、保底和历史在同一事务写入。相同 ID、相同参数重试返回原结果，不再扣券；同一 ID 改参数会被拒绝。前端保留未确认请求，断线后可恢复。最近 100 条记录可见，请求去重记录保存在数据库。首通奖励与通过版本检查的进度写入也在同一事务内。

v0.9 的卡背揭晓、六星出场和免费卡面鉴赏都是客户端展示，不改变概率、保底、余额或角色持有状态。鉴赏不调用抽卡接口；跳过演出仍展示服务器已经返回的结果。静态白名单包含 `assets/cards/*.png` 主题卡面，八位伙伴与男女主角共十张重制立绘用于大厅和过场。图片生成方式与视觉研究见项目根目录 `assets/cards/ART-DIRECTION.md`。

## 数据与备份

数据库默认位于 `%LOCALAPPDATA%/WildsAndWonders/Server/accounts.sqlite`，使用 SQLite WAL，包含账号、密码哈希、会话、进度、收藏和抽卡去重记录。发行包不包含玩家数据库。

备份时关闭连接到此服务的窗口，停止对应 `node.exe server.cjs` 进程，再复制整个 `Server` 目录，包括可能存在的 WAL / SHM 文件。不要上传到公开仓库或放入发行包。升级保持数据目录不变。旧版本占用端口时只需停止这份游戏的服务，无需终止其他项目的 Node 进程。

## 接口与实现

| 接口 | 用途 |
| --- | --- |
| `GET /api/health` | 服务版本、游戏目录 |
| `POST /api/register`、`POST /api/login` | 注册、登录，返回进度与收藏 |
| `GET /api/me`、`POST /api/logout` | 当前账号、退出 |
| `PUT /api/profile` | 携带 revision 保存、校验角色持有并结算首通奖励 |
| `GET /api/collection` | 券、星尘、角色、武器、装备、保底、历史 |
| `POST /api/draw` | 指定池单抽 / 十连，需 requestId |
| `POST /api/equip` | 装备、转交或卸下 |
| `POST /api/exchange` | 100 星尘换 1 券 |

同源 JSON 请求，HttpOnly / SameSite=Strict 会话 Cookie；客户端不存密码或可读取会话令牌。密码使用独立随机 salt 的 scrypt 哈希，数据库采用参数化查询和事务；限制请求体、哈希并发和认证频率。HTTP 仅用于本机回环，未配置公网 TLS。

`server/server.cjs` 管理 HTTP、账号、会话、进度和静态白名单；`server/gacha.cjs` 管理招募、收藏、奖励和装备；客户端入口为 `account.js` 与 `gacha.js`。

## 验证与构建

在项目根目录运行：

```powershell
node server/test.cjs
node server/gacha-test.cjs
node server/client-races-test.cjs
node test.cjs
./build.ps1 -OutputFolder release/WildsAndWonders-v0.9
./release/WildsAndWonders-v0.9/WildsAndWonders.exe --smoke-test
```

账号测试覆盖真实 HTTP、持久化、账号隔离、输入校验、会话注销 / 过期、并发存档、来源限制和文件访问。招募测试穷举基础概率和保底边界，检查重试不重复扣券、四池独立、余额事务、首通奖励、装备互斥、历史上限、重启持久化和旧账号迁移。`client-races-test.cjs` 检查账号切换后的迟到响应隔离和音乐最小化 / 恢复。战斗测试包含 20 关模拟，桌面检查真实页面、招募、剧情、装备与音乐解码。

桌面测试使用独立 18767 端口和测试数据库，不接触玩家账号。`build.ps1` 生成 Windows 目录与 ZIP；本地构建不会自动更新 GitHub 已发布版本。

实现参考：[Node.js SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)、[Node.js crypto / scrypt](https://nodejs.org/download/release/v24.19.0/docs/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)。
